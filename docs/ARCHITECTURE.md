# Architecture

The contract every part of gma.4mn.org is built against. `VISION.md` says what the app is for; `docs/DECISIONS.md` records why it is built this way. When this file and the code disagree, fix one of them in the same change.

## Shape

```
phones (family PWA) ─┐                                 ┌─ app    10.35.0.2 (Fastify: PWA, API, SSE, tus uploads, media)
                     ├─ Cloudflare ─ tunnel 10.35.0.3 ─┤
Grandma's Pi (kiosk) ┘   (gma-tunnel, cloudflared)     └─ worker 10.35.0.4 (jobs: images, video, voice → renditions; nightly snapshot)
                                                             │
                                both read/write  /data/gma.sqlite   (SQLite, WAL; the gma_data volume on the SSD)
                                                 /media/originals, /media/renditions, /media/backups
                                                                    (gma_media, bound to /mnt/seagate/gma/media)
```

- One Docker image, two services: `app` (`node src/index.js`) and `worker` (`node src/worker.js`). Both share the SQLite database and the media volume. A third container, `gma-tunnel`, is gma's own Cloudflare tunnel, straight to `http://app:8080` on the compose network (`docker-compose.yml` at the repo root, `deploy/cloudflared.yml`); no nginx, and nothing listens on the LAN (`127.0.0.1:3064` is for checks from the box itself).
- The media live on the Seagate drive and the database on the SSD (DECISIONS, 2026-10-22). If the drive isn't mounted, Docker can't bind `/mnt/seagate/gma/media`, and the app and the worker also refuse to start without the `MEDIA_SENTINEL` file (`/media/.gma-media`): they log one line and exit 78, so photos are never written to the SSD under an empty mount point. If the drive drops while they run, `/healthz` answers 503 with `media: false` (so `docker compose ps` shows the app unhealthy), the worker's healthcheck fails, and the worker stops claiming jobs until the sentinel is back (see Media pipeline). Recovery after a drop: `docker compose down && docker compose up -d` once the drive is mounted again (`deploy/backup.md`).
- Everything runs on Ben's Debian homelab. If his internet is down, the app is down. That's accepted. Grandma's frame keeps showing saved photos (see Offline).
- No external services, except the email sender for sign-in codes and invites (Ben's Gmail over SMTP; Resend is the other choice) and the browsers' push services.

## Stack

| Layer | Choice |
|---|---|
| Edge | gma's own `cloudflared` container (`gma-tunnel`, named tunnel, `deploy/cloudflared.yml`) straight to `http://app:8080` on the compose network; no nginx, nothing published on the LAN but `127.0.0.1:3064` |
| Runtime | Node 24 LTS in Docker (`node:24-trixie-slim`). The code also runs on Node 25 locally. ESM (`"type": "module"`). |
| HTTP | Fastify 5, `@fastify/cookie`, `@fastify/static`, `@fastify/rate-limit` |
| Database | `better-sqlite3` 13, WAL, `busy_timeout=5000`, `foreign_keys=ON`. Every write transaction is `BEGIN IMMEDIATE` (`lib/tx.js::immediate`), so two processes never hit SQLITE_BUSY on a read-then-write. Migrations are plain SQL files run in order at start, after a copy of the database (see Media pipeline → snapshots). |
| Uploads | tus: `@tus/server` 2 + `@tus/file-store` in Fastify; the browser uses `tus-js-client` 4 (vendored ESM build) with `chunkSize` 32 MB |
| Images | prebuilt `sharp` (JPEG/PNG/WebP/AVIF); HEIC/HEIF is first decoded by the `heif-dec` CLI (Debian `libheif-examples`) |
| Video and voice | `ffmpeg`/`ffprobe` (Debian trixie) spawned by the worker |
| Passkeys | `@simplewebauthn/server` 14 + `@simplewebauthn/browser` 14 (vendored) |
| Push | `web-push` 3.6 (VAPID) |
| Email | `nodemailer` 10 over SMTP (Gmail with an app password); Resend REST API via `fetch` (no SDK); `console` transport for dev and tests |
| Frontend | vanilla JS ES modules + custom CSS, no build step, no framework. Heirloom design (`design/heirloom/`). |
| Tests | `node --test` + `fastify.inject` for the server; `node --test` for pure web modules; Playwright 1.58 (headless shell, never Google Chrome) for end-to-end |

## Configuration (`.env`, never committed; `.env.example` lists every key)

| Key | Default | Notes |
|---|---|---|
| `NODE_ENV` | `production` | `development` relaxes `Secure` cookies on `http://localhost` |
| `PUBLIC_URL` | (required in production) | origin used for links, the Origin check, WebAuthn's expected origin; `http://localhost:<PORT>` in development and test |
| `HOST` / `PORT` | `0.0.0.0` / `8080` | inside the container |
| `DATA_DIR` | `/data` | `gma.sqlite` lives here (`<repo>/data` in development and test) |
| `MEDIA_DIR` | `/media` | `originals/`, `renditions/`, `uploads/` (tus scratch), `backups/` (the nightly database snapshots and the pre-migration copies); `<repo>/media` in development and test |
| `MEDIA_SENTINEL` | `.gma-media` in production, else empty | a plain file name that must exist in `MEDIA_DIR` before the app or the worker starts (proof the drive is mounted); empty or `off` turns the check off. Compose pins it. Checked at start, by `/healthz`, by the worker's healthcheck and before every job claim |
| `WEB_DIR` | `<repo>/web` | optional; where the static web app is served from |
| `SECRET_KEY` | (required in production) | ≥ 32 random bytes, base64; HMAC key for codes and token hashes; a fixed dev key in development and test |
| `EMAIL_TRANSPORT` | `console` | `console`, `smtp` or `resend`. Production uses `smtp` (Ben's Gmail), set up by `deploy/use-gmail.sh`; `console` only until then. See Email below |
| `EMAIL_FROM` | `"Grandma's family" <SMTP_USER>` with `smtp`, else `Grandma's family <hello@auth.4mn.org>` | with `smtp`, an address other than `SMTP_USER` logs a one-line warning at start: Gmail rewrites From to the account unless it's a verified "Send mail as" alias |
| `SMTP_HOST` / `SMTP_PORT` | `smtp.gmail.com` / `465` | `smtp` only; the port is a number from 1 to 65535 |
| `SMTP_SECURE` | `true` on port 465, else `false` | implicit TLS; when false (587), STARTTLS is required, so the password never crosses in the clear |
| `SMTP_USER` / `SMTP_PASS` | (required with `smtp`) | the Gmail address and a 16-letter app password (Google's spaced `abcd efgh ijkl mnop` is accepted). `SMTP_PASS` is never logged, never in an error, and left out of the config's keys |
| `RESEND_API_KEY` | (required with `resend`) | |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` | (required for push) | `npm run vapid:gen` once; never rotate (it orphans every subscription) |
| `VAPID_SUBJECT` | (required) | a real `mailto:` (Apple rejects placeholders) |
| `WEBAUTHN_RP_ID` | host of `PUBLIC_URL` | `gma.4mn.org` |
| `WEBAUTHN_RP_NAME` | `Grandma's family` | shown in the passkey sheet |
| `MAX_UPLOAD_BYTES` | `2147483648` | 2 GB per file |
| `MAX_VIDEO_SECONDS` | `180` | longer videos fail with a kind message |
| `MAX_VOICE_SECONDS` | `60` | recorder stops itself; server trims at 65 s |
| `TRUST_PROXY` | `true` in production, else `false` | `true`, `false`, or a comma-separated list of proxy IPs/CIDRs (a frozen array). Compose pins it to the tunnel's `10.35.0.3`, so only that peer's `X-Forwarded-For` and `CF-Connecting-IP` are believed. A malformed entry is a `ConfigError` at start |
| `LOG_LEVEL` | `info` (`silent` in test) | |
| `GMA_TUNNEL_CREDENTIALS` | (required by compose) | read by `docker-compose.yml` only, never by the app: the host path of the named tunnel's credentials JSON, mounted read-only into `gma-tunnel` as `/etc/cloudflared/credentials.json`. Compose refuses to start without it |

`loadConfig(env)` (`server/src/config.js`) returns a frozen object whose keys are these names in camelCase (`publicUrl`, `secretKey`, `emailTransport`, `resendApiKey`, `emailFrom`, `smtpHost`, `smtpPort`, `smtpSecure`, `smtpUser`, `smtpPass` (readable but not enumerable, so `JSON.stringify` and `util.inspect` never print it), `vapidPublicKey`, `vapidPrivateKey`, `vapidSubject`, `webauthnRpId`, `webauthnRpName`, `maxUploadBytes`, `maxVideoSeconds`, `maxVoiceSeconds`, `trustProxy`, `logLevel`, `dataDir`, `mediaDir`, `mediaSentinel`, `webDir`, `host`, `port`, `nodeEnv`), plus `isProduction`, `publicOrigin`, `dbPath` (`<dataDir>/gma.sqlite`) and `cookieSecure` (true unless `PUBLIC_URL` is plain http outside production). It throws a `ConfigError` with a readable message for a missing or malformed value. `loadConfig(env, { warn })`: `warn(line)` receives the warnings that don't stop a start (default `console.warn`, silent under `NODE_ENV=test`).

## Data model (SQLite, `server/src/db/migrations/001_init.sql` … `005_kinship_short_names.sql`)

All ids are 26-char ULIDs (`lib/ids.js::newId()`) except passkey credential ids. All times are integers, milliseconds since the epoch, UTC. Booleans are 0/1.

`users.short_name` is what Grandma calls the person ("Mike", "Grandpa Joe"); the frame shows it wherever it shows a person, and the family app shows `name`. It defaults to the first word of `name`, unless the name starts with a family or title word (aunt, uncle, cousin, grandma, grandpa, nana, great, great-aunt, tía, big, little, mr, dr … the full list is `FAMILY_WORDS`): then it is that word and the next ("Uncle Mike", "Aunt Carol"), or the first three when the first two are both family words ("Great Aunt Mary"). A default over 30 characters drops leading family words, never the given name; words are compared in ASCII lower case. The rule lives in three places that must stay equal, and `server/test/short-names.test.js` checks they do: `lib/people.js::defaultShortName` (the server), the trigger from migration 005 (every row inserted without one; a short name that is still a default follows a rename, one someone chose is kept; 005 also recomputed the old first-word defaults) and `web/shared/names.js::shortNameFor` (the join form's prefill, `/admin`, and the family app's "To Uncle Mike" lines). A relative can set it when joining ("What does Grandma call you?", sent as `short_name` with the accept), and Ben edits both with `PATCH /api/admin/people/:id`. `devices.created_by` is NULL when the CLI paired the device. Media paths (`items.original_path`, `renditions.path`, `voice_notes.original_path`/`audio_path`) are storage *keys*, relative to `MEDIA_DIR` (see Server core). Seed rows in the migration: the 8 presets ("Love you", "Call me", "Thank you", "Miss you all", "So beautiful", "Made my day", "Come visit soon", "Proud of you") and the default settings.

## Sessions, auth and devices

- **Cookie** `gma_session`: random 32-byte token (base64url), only its SHA-256 is stored. `HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=34560000` (400 days, Chrome's cap). Each request touches `last_seen_at`; past half its life the expiry is pushed out (sliding). `lib/sessions.js` owns `createSession(db, {kind, userId|deviceId, userAgent})`, `setSessionCookie(reply, token)`, `clearSessionCookie(reply)`, `loadSession(db, token)`, `revokeUserSessions(db, userId)`, `revokeDeviceSessions(db, deviceId)`.
- **Guards** (`lib/guards.js`, Fastify preHandlers): `requireUser`, `requireAdmin`, `requireDevice`, `requireUserOrDevice`. They set `request.user` or `request.device`. Removed users and revoked devices are 401.
- **CSRF**: every state-changing request (`POST/PUT/PATCH/DELETE`) must carry an `Origin` header equal to `PUBLIC_URL`'s origin (tus requests included). JSON bodies only, no form posts, plus SameSite=Lax.
- **Invite** (admin-made, single use, 14 days): `/join/<token>`. If the app emailed the invite to that address, opening the link proves the email and signs them in straight away. If Ben shared the link some other way (a text), they type their name and email and confirm with a code. A user is `pending` until that first sign-in. Accepting marks the invite used by that pending person (and records them as `invites.created_user_id`), but it stays usable until they finish signing in, so a mistyped email is fixed by opening the link again (the same pending person gets the new address). An invite only ever edits the person it created: typing the address of anyone else (someone who already has an account, or a relative still pending through their own invite) only sends that person a code at their own address and leaves both them and the invite alone (never renamed, never re-addressed, never `used_by`), unless the link proves that address. A removed person's address is refused. An invite never changes an existing person's role. On the code screen, "Use a different email" goes back to the invite form, and both the code screen and `/signin` say that codes only go to the address someone was invited with.
- **Email code** (the reliable path on iPhone, where the installed app has its own cookie jar): 6 digits, valid 15 min, 5 attempts, the newest code wins. Stored as an HMAC. The same email carries a link to `/confirm?t=<token>`. That page needs a button tap (a POST) to sign in, so mail scanners that open links can't burn it. Using the `/confirm` link uses up only the link, never the code from the same email: Mail opens links in Safari, and the Home Screen app (its own cookie jar) can still take the code; using the code ends the link. On an iPhone outside the installed app, `/confirm` says to go back to the app and type the code. Rate limits: 5 code requests per email per hour and 20 per IP per hour; after 15 wrong codes for one person in a day (across all their codes, `MAX_FAILED_CODES_PER_DAY`) no code is sent or accepted for that email until the day is over (the answers don't change). `POST /api/auth/code/request` always answers 200, so it never reveals who has an account (the email is sent without waiting, so the timing doesn't tell either, and the per-email limit silently sends nothing). Other per-IP limits: code verify and link confirm 30 per 15 min, passkey login 30 a minute, invite lookups 60 a minute, invite accepts 20 an hour. The per-IP key is `request.clientIp` (`lib/client-ip.js`): `CF-Connecting-IP` only when the socket peer is a trusted proxy (`TRUST_PROXY`) and the header is one valid IP, else `request.ip`; an IPv6 client's whole /64 counts as one.
- **Passkeys** ("Use Face ID next time"): after the first sign-in (and after any code sign-in on a device without one, at most 3 offers), and only where `PublicKeyCredential.isUserVerifyingPlatformAuthenticatorAvailable()` says the phone can make one, the app offers to create a passkey (discoverable credential, `residentKey: 'required'`, `userVerification: 'required'`, attestation `none`, RP ID `gma.4mn.org`). Later sign-ins use "Sign in with Face ID" (a usernameless `navigator.credentials.get`). The email code stays as the fallback and the recovery path. Verified rules (`docs/research/passkeys-research.json`): `create()`/`get()` run only from a tap, never on load; no conditional/autofill UI (it is unreliable in the installed iOS app); challenges are server-side, single use, 5 min; `requireUserVerification: true`; synced passkeys keep counter 0 (not a clone signal); one gentle error for every `NotAllowedError` ("That didn't work. Try again or get an email code."). A failed set-up on an iPhone explains the passcode and iCloud Keychain, and after two failures only "Continue" is left; a phone that refuses because it already holds the person's synced passkey (`InvalidStateError`) counts as set up. The installed iPhone app (which can't see Safari's passkey hint) leads its sign-in screen with Face ID. The client fetches options before the tap (iOS loses a tap that waits on the network) but never while a ceremony is running: the server keeps one pending challenge per browser, so a second options call would replace the challenge the sheet is signing (`web/app/passkeys.js::prefetchOptions`; refresh only after a failure). iCloud Keychain must be on for iPhone passkeys; the code path covers everyone else. Grandma's frame never uses passkeys. A user can hold several passkeys and remove them on the You screen. Removing a user deletes their passkeys and sessions.
  - Implementation (`lib/webauthn.js`, `routes/auth.js`): the challenge is tied to the browser by the `gma_webauthn` cookie (HttpOnly, SameSite=Strict, path `/api/auth/passkey`, 5 min) holding the challenge row id plus an HMAC of it; the verify routes read the challenge from that row, never from the client, and delete it on first use. Registration also sets `authenticatorAttachment: 'platform'` (SimpleWebAuthn's `preferredAuthenticatorType: 'localDevice'`), so nobody lands on the security-key sheet; the user handle is an HMAC of the user id (stable, opaque); the label is the provider's name from the AAGUID ("Apple Passwords", "Google Password Manager", …, else "Passkey"). A sign-in's `userHandle`, when sent, must match. An unknown credential, or one whose owner was removed, is 404 `unknown_credential` (the client then calls `signalUnknownCredential` where supported and offers the email code).
  - The offer (`offer_passkey`, in the sign-in answers and `/api/me`): at most one offer per session and 3 per device, never on a device that signed in with or made a passkey. The count lives in the `gma_passkey_offers` cookie (HttpOnly, 400 days: `<count>.<session id last offered>` or `done`), so it survives a new session on the same phone; a passkey sign-in answers `offer_passkey: false`.
- **Grandma's frame**: Ben pairs a device in `/admin` (or `npm run device:pair`). That makes a 32-byte token, shown once as `https://gma.4mn.org/grandma?device=<token>`. `GET /grandma?device=` checks the token, creates a `device` session (cookie), and 302s to `/grandma/` with the token stripped from the URL. The kiosk launches with that URL, so a wiped browser profile pairs itself again at the next boot. Request logs redact the `device`, `t`, `token` and `code` query parameters and the invite token in `/join/<token>` and `/api/invites/<token>…`.

## HTTP API

JSON in and out. Errors are `{error: {code, message}}`, and `message` is a sentence a person can read. Pagination is `?before=<id>&limit=` with ULID cursors.

| Area | Route | Guard | Notes |
|---|---|---|---|
| Health | `GET /healthz` | public | `{ok, db, media, worker_last_seen}`, `no-store`; 503 with `ok: false` when the database can't be read or the drive's sentinel is gone (`media: false`) |
| Invites | `GET /api/invites/:token` | public | `{valid, name, email, emailed, reason}`; `reason` is `unknown`, `expired`, `revoked` or `used` when not valid; `emailed` = the app mailed it to `email` |
| | `POST /api/invites/:token/accept` `{name, email, short_name?}` | public | creates/updates the pending user. `short_name` (what Grandma calls them, ≤ 30 characters, else 400) is set only on the invite's own person; without it the default applies. Emailed to that address → signs in: `{signed_in: true, user, offer_passkey}`; otherwise sends a code: `{signed_in: false, email}`. Errors `invite_unknown` 404, `invite_expired`/`invite_revoked`/`invite_used` 410, `account_removed` 403 |
| Auth | `POST /api/auth/code/request` `{email}` | public | always 200 `{ok: true}`, answered before the address is looked up (the lookup, the code and the email run just after, in `setImmediate`, so real and unknown addresses take the same path); a malformed email is 400 `invalid_email`; over 20 per IP per hour is 429 |

## Live events (SSE)

The `events` table is an outbox. Anything that changes state (the app or the worker) inserts a row (`lib/events.js::publish(db, topic, payload, audience = 'all')`, which returns the row id). Audiences: `all` (every user and device), `devices` (frames), `user:<id>`, `device:<id>` (one frame, e.g. `frame.reload` from the admin's Reload button). The app polls it every second and fans new rows out to connected clients that match the audience. Event ids are the row ids, so `Last-Event-ID` resumes after a reconnect. Topics: `item.ready`, `item.removed`, `item.failed` (owner only), `grandma.event`, `settings.changed`, `frame.reload` (devices). Rows older than 7 days are deleted.

On the wire each event is `id: <row id>`, `event: <topic>`, `data: <payload JSON>`, so clients listen with `source.addEventListener('item.ready', …)` (`onmessage` sees nothing). The stream opens with `retry: 3000`. If a reconnecting client missed more than 500 events, or some were already pruned, it gets one `resync` event (`data: {}`) instead and should reload its state.

## Media pipeline (worker)

`jobs` is claimed with `UPDATE … SET status='running', locked_at=?, locked_by=? WHERE id = (SELECT id FROM jobs WHERE status='queued' AND run_after<=? ORDER BY created_at LIMIT 1) RETURNING *`. Concurrency: video 1, image 2, voice 1. Retries back off exponentially (30 s, 2 min, 10 min), with 3 attempts. Jobs are idempotent: each writes to a temp path and renames into place, and the bookkeeping (claim, complete, fail, release) runs in IMMEDIATE transactions; a throw from it (SQLITE_FULL, say) is logged and never becomes an unhandled rejection (`worker.js` logs those too).
- **Reclaiming jobs a dead worker left running** (`queue.js`): at boot, `requeueRunning()` requeues every `running` job, however young its lock (there is one worker, and its fresh id owns none of them), keeping the attempt it already used. Every 10 minutes `sweepStale()` does the same for locks older than `STALE_LOCK_MS` (2 h, longer than the longest transcode) held by another worker or none; it never touches this worker's own jobs. Compose runs exactly one worker, and that must stay true: a second one starting next to a live one would take its jobs at boot.
- **Poison jobs**: in both paths a job that has used all its attempts is not requeued but fails for good with `crashMessage()` ("The worker stopped while this job was running (it crashed, ran out of memory or lost power) 3 times, so it was given up."), shown in admin health's `recent_failures`, and the handler's `onFailed` runs (the item turns `failed`). There is no retry button yet: a job that failed for good needs SQL to run again.
- **The drive**: the runner checks the media sentinel (`storage.isMounted()`) before each claim and stops claiming while it is gone, logging once when it goes and once when it is back. A job that fails while the sentinel is missing is released without spending an attempt and tried again after 60 s. I/O errors on media paths (`EIO`, `ENOENT`, `ENXIO`, `ESTALE`, `ENODEV`, `ENOTCONN`; `jobs/errors.js::mediaIoError`) are ordinary retries, never a permanent "unreadable photo"; only a decode failure is. The worker writes `worker_last_seen` to settings every 15 s. A permanent failure (a video over the limit, an unreadable photo) skips the retries. When the last attempt fails, the item becomes `failed` with a kind sentence in `items.error` and `item.failed` `{item_id, error}` goes to `user:<owner>`; `item.ready` is `{item_id, user_id, kind, batch_id}` to `all`; the voice job's `grandma.event` is `{id, kind: 'voice', voice_note_id, item_id}`. The video limit is the lower of `MAX_VIDEO_SECONDS` and the `max_video_seconds` setting. On SIGTERM the runner lets running jobs finish for 20 s, then cancels them and requeues them without spending an attempt (compose gives the worker 40 s). A job whose item or voice note was deleted while it ran (`isGone()` in each job module) is completed as done, with no retry and no `onFailed`. ffmpeg runs with two threads (`FFMPEG_THREADS`); compose caps the worker at 3 CPUs and 3 GB of memory (the app at 1 GB, the tunnel at 256 MB; each with a `pids_limit`). - **Snapshots**: the runner also makes the nightly database snapshot (`jobs/snapshot.js`, see Admin → Health); it refuses, before claiming the day, when the drive's sentinel is missing. Before migrating, the app and the worker each call `db/index.js::snapshotBeforeMigrations()`: when an existing database has migrations pending, it is copied with SQLite's backup API to `MEDIA_DIR/backups/pre-<first pending migration>-<UTC time>.sqlite` (through a `.gma-*.tmp` file that the nightly pruning clears if a crash leaves one; one copy per first pending migration, so whichever of the two processes starts first makes it and the other skips), after the sentinel check. If that copy fails (a full drive), the process refuses to start (exit 1) rather than migrate with no way back. The nightly pruning keeps the pre-migration copies; delete them by hand when they are no longer needed.

## Push (who gets what)

`lib/push.js` exports `sendToUser(db, config, userId, payload)`, `sendToAll(db, config, payload)` and `notifyGrandmaEvent(db, config, eventId)` (builds the payload below from the event and sends it to the right people; safe to call from the app or the worker). Reactions and presets call it from the frame route right after inserting the event; voice notes call it from the voice job.

| Grandma does | Push goes to | Payload (declarative web push, ≤ 2 KB) |
|---|---|---|
| Reacts to a photo | the item's owner | `{"web_push": 8030, "notification": {"title": "Grandma loved your photo", "body": "❤️ Love · “Lily at the farm…”", "navigate": "<PUBLIC_URL>/from-grandma#e-<id>", "tag": "grandma-<item_id>"}}` (a later reaction on the same photo replaces it) |
| Sends a preset | the item's owner | title `Grandma sent you a message`, body `“Call me” · about your photo`, tag `grandma-message-<event id>` (its own, so a reaction never replaces a message) |
| Records a voice note | every active user | title `Grandma sent a voice message`, body `Tap to listen (0:42)`, tag `grandma-voice-<id>` |

TTL 2 days, urgency `normal`. A 404/410 deletes the subscription. Another definite refusal from the push service (a 4xx other than 408 and 429; `lib/push.js::countsTowardDrop`) increments `failures`, and the subscription is dropped after 5 in a row; network errors (no status), 408, 429 and 5xx are transient and never count. A success resets the count. The service worker's `push` handler always calls `showNotification` with the same fields, so iOS never revokes it for a silent push. Its `notificationclick` focuses or opens `navigate`. The client re-syncs its subscription each time the app opens. On iOS the Enable button only appears in standalone mode, and it requests permission from that tap.

Each request has a timeout (20 s for JSON, 120 s for a voice note; `grandma/lib/api.js::REQUEST_TIMEOUTS`), which counts as offline and is retried, so one stalled upload never holds the rest.

## Server core (the shared pieces feature routes build on)

- **`buildApp(config, { db?, routesDir?, routeOptions?, plugins? })`** checks the media drive first (`storage.init()`, which throws `MediaNotMountedError` before anything is created), then opens the database (unless `db` is passed), decorates `app.config`, `app.db`, `app.storage` (`createStorage(config.mediaDir, { sentinel: config.mediaSentinel })`), `app.events` (the SSE hub), `request.clientIp` (set for every request in an `onRequest` hook; see Sessions, auth and devices) and `request.user` / `request.device` / `request.session` (null until a guard or `authenticate` runs), then registers every `src/routes/*.js` in name order with opts `{ config, db }` (each file is its own encapsulated plugin) and calls `ready()`.
- **Errors**: throw `httpError(status, code, message)` (from `lib/guards.js`), or any error with `statusCode` and a snake_case `code`; the handler sends `{error: {code, message}}`. 5xx bodies are always the generic sentence (the real error is logged). Unknown routes are a JSON 404.
- **Bodies**: JSON only; the `text/plain` parser is removed. A route plugin that needs another body type registers it *inside its own plugin*: the uploads plugin removes every parser and adds only `application/offset+octet-stream` for tus (never buffered; any other body is a 415 before it is read, and its routes authenticate in `onRequest`), the frame plugin registers `@fastify/multipart` for `POST /api/frame/voice` (it is not registered globally).
- **Rate limits** are opt-in per route: `{ config: { rateLimit: { max, timeWindow, keyGenerator? } } }`, or `{ config: perIp(max, timeWindow) }` from `lib/rate-limits.js`; the default key is `rateLimitKey` (`lib/client-ip.js`: the client, never the proxy; an IPv6 /64 as one). A 429 is `{error: {code: 'rate_limited', …}}`, worded from the time the limiter has left: more than 15 minutes (the hourly limits: code requests, invite accepts, admin invites, uploads per hour) says "Please wait an hour and try again.", less keeps "a few minutes".
- **Guards** (`lib/guards.js`): `requireUser`, `requireAdmin` (401 signed out, 403 member), `requireDevice`, `requireUserOrDevice`, plus `authenticate(request, reply)` for routes that want the session without requiring one. A guard re-sets the cookie when the session slid.
- **Sessions** (`lib/sessions.js`): `createSession(db, {kind, userId|deviceId, userAgent})` → `{token, id, expiresAt}`; `loadSession(db, token)` → `{session, user, device, renewed}` or null (touches `last_seen_at`, and the device's, at most once a minute); `setSessionCookie(reply, token)`, `clearSessionCookie(reply)`, `readSessionToken(request)`, `destroySession(db, token)` (logout), `revokeUserSessions(db, userId)`, `revokeDeviceSessions(db, deviceId)`, `SESSION_COOKIE`.
- **Tokens** (`lib/tokens.js`): `randomToken(bytes = 32)` (base64url), `randomDigits(6)`, `sha256(value)` (hex, for tokens), `hmac(config.secretKey, value)` (hex, for codes), `safeEqual(a, b)`. **Ids**: `newId()`, `isId()`, `idTime()`. **Time**: `now()`, `setClock()` (tests), `SECOND`…`DAY`, `clockInZone(ms, tz)`, `inWindow(hhmm, start, end)`, `isNight(ms, settings)`, `isValidClockTime()`.
- **Settings** (`lib/settings.js`): `getSetting(db, key, fallback?)`, `setSetting(db, key, value)`, `getSettings(db, keys?)` (defaults filled in), `setSettings(db, object)`, `DEFAULT_SETTINGS`.
- **Email** (`lib/email.js`): `sendEmail(config, {to, subject, text, html})`, `signInCodeEmail({name, code, confirmUrl})`, `inviteEmail({name, inviterName, joinUrl})`, `testEmail({publicUrl, transport})`, `escapeHtml()`; `captureEmails(config)` returns the array that receives that config's mail instead of sending it (the test hook), and `useSmtpFactory(config, factory)` hands the smtp transport a fake nodemailer (tests never open a socket).
  - Transports: `console` prints the message and returns `printed: true`; `smtp` (`smtpOptions(config)`) makes a nodemailer transport per message (no pool: a few emails a day), with `SMTP_TIMEOUTS` of 10 s to connect, 10 s for the greeting and 20 s of socket silence, `logger`/`debug` off and file and URL access off; `resend` posts to Resend's API with a 10 s timeout. Only a message SMTP or Resend accepted counts as emailed (an invite's `sent_at`); a printed one never does.
  - Failures throw an `EmailError` with a sentence of ours, nodemailer's code and the SMTP reply code (`The email server refused the sign-in: check SMTP_USER and SMTP_PASS; Gmail needs an app password (EAUTH 535)`), `status`, `code` and the recipient's `domain`. nodemailer's own message never passes through (it can quote the reply, the recipient and the AUTH command), and neither does the original error as `cause`. The sign-in code path logs it and still answers 200 (the unsent code is deleted so it doesn't count against the hourly limit); the admin invite send answers 424 `email_failed`.
  - Gmail sends about 500 emails a day from one account (a sign-in code or an invite each); gma's family needs a handful. Setting it up: `deploy/use-gmail.sh` (README → Deploy). Checking it: `npm run -s email:test -- --to <address>` (`scripts/email-test.js`) sends one short email and prints only `sent` or the error's class and message.
- **Transactions** (`lib/tx.js`): `immediate(db, fn, ...args)` = `db.transaction(fn).immediate(...args)`. Every write transaction goes through it; a test fails if a bare `db.transaction(` appears anywhere else in `src`.
- **Storage** (`lib/storage.js`): `createStorage(mediaDir, { sentinel })` → `{init(), isMounted(), originalKey(id, ext, createdAt), renditionKey(id, name, ext), resolve(key), ensureDirFor(key), tempPathFor(key), remove(key), removeRenditions(id), originalsDir, renditionsDir, uploadsDir, backupsDir}`; `init()` calls `assertMediaMounted(mediaDir, sentinel)` (throws `MediaNotMountedError`, code `media_not_mounted`) before any `mkdir`; `safeJoin(root, …parts)`. Keys look like `originals/2026/10/<id>.heic` and `renditions/<id>/display.jpg`; a voice note's audio is `renditions/<voiceId>/audio.m4a`. `resolve` throws `UnsafePathError` on traversal.
- **Redaction** (`lib/redact.js`): `redactUrl(url)` (request logs; `device`, `t`, `token`, `code`, plus the invite token in `/join/<token>` and `/api/invites/<token>…`, via `redactPath`), `stripSecretParams(url)` (redirect targets).
- **Pages**: `/` signed out is the landing page, `web/landing.html` (200, `no-cache, no-transform`, noindex by header and meta like every page): a short, generic explanation of the frame for anyone who has the link, with Sign in (`/signin`) and "Got an invite? Open the link in your email." It is static and strict-CSP clean (no script, no inline style, nothing from another origin), styled by `/shared/tokens.css` and `/landing.css`, with two real screenshots in `/assets/landing/` (the frame's Home fixture at 1280x800 and Grandma's Feed at 390x844, WebP at two widths each, remade with `LANDING_CAPTURE=1 bash web/e2e/run.sh landing.spec.js`). `/` with a user session is the shell as before; with a device session (the frame) it 302s to `/grandma/`. Every other signed-out visit to a private page 302s to `/signin?next=<path>` (secret parameters stripped; `next` is only ever a same-origin path, checked as `new URL(next, origin).origin === origin` and not starting with `//` (a dot segment can collapse into one) by the server when it writes it and by the sign-in screen when it follows it, else `/`); `/admin*` sends members to `/`; `/grandma/` and `/grandma/index.html` need a device session or an admin (the static handler never serves the frame's page, however the path is spelled; the frame's JS, CSS, `sw.js` and `version.js` stay public). The shell is identical on every family path, so the family service worker precaches it from the public `/signin`; every shell response carries `x-gma-page: shell`, and the worker keeps a page as its offline copy (`/__shell`) only with that header, so the landing page at `/` never replaces it. Caching: `/assets/*` one year immutable (rename a file to change it), `/vendor/*` 30 days, HTML `no-cache, no-transform` (no-transform keeps Cloudflare from injecting its Web Analytics beacon or otherwise rewriting a page), JS, CSS, service workers and the manifest plain `no-cache` (so Cloudflare still compresses them), all with ETags. Both service workers register with `updateViaCache: 'none'` and precache with `cache: 'reload'`, so Cloudflare's 4-hour Browser Cache TTL (until the Cache Rule in `deploy/cloudflared.md` §3 is added) can't hide a new version from them. The frame's "not set up" page is 403, `no-store, no-transform`, no cookie, styled by `/grandma/not-set-up.css`.
- **Plain http through the tunnel**: a request from a trusted proxy (`TRUST_PROXY`) with `X-Forwarded-Proto: http`, when `PUBLIC_URL` is https, gets a 301 to the same path and query on `PUBLIC_URL`'s origin (GET and HEAD) or 400 `https_required` (anything else). Requests that didn't come through a trusted proxy (local, the box's `127.0.0.1:3064` debug port) are never redirected.
- **Worker**: `src/worker.js` checks the drive right after loading the config (no sentinel: one clear line and exit 78, like `src/index.js`), makes the pre-migration copy if migrations are pending, opens the database, writes `worker_last_seen` every 15 s itself (`scripts/worker-health.js`, the container's healthcheck, wants it under a minute old and fails when `MEDIA_DIR` or its sentinel is missing), logs any unhandled rejection, and calls `startRunner({config, db, storage, log})` exported by `src/jobs/runner.js`, which returns `{stop()}` (awaited on SIGTERM). Without that file it logs and exits 1.

## Security and privacy

- Nothing public: every page except `/join`, `/signin`, `/confirm`, `/grandma?device=` and `/healthz` needs a session. Every response carries `X-Robots-Tag: noindex, nofollow`; `robots.txt` disallows all.
- Headers: a strict CSP (`default-src 'self'`; `img-src 'self' blob: data:`; `media-src 'self' blob:`; no inline script and no inline style either: no `<style>` blocks or `style="…"` attributes in HTML, set `element.style` from JS instead; `frame-ancestors 'none'`), `X-Frame-Options: DENY`, `Cross-Origin-Opener-Policy: same-origin`, HSTS when `PUBLIC_URL` is https, `Referrer-Policy: no-referrer`, `Permissions-Policy: microphone=(self), camera=()`, `X-Content-Type-Options: nosniff`.
- Secrets only in `.env`. Tokens and codes are stored hashed. Logs never contain tokens, codes, email bodies, recipients' addresses (only their domain) or the SMTP password, with one stated exception: `EMAIL_TRANSPORT=console` (development, and a new deploy before Gmail is set up) prints each message to the app log. An invite the console transport printed doesn't count as emailed (`sent_at` stays NULL, so opening it still asks for a code); `sendEmail` returns `printed: true` for it.
- Location data is stripped from every rendition. Originals are never served.
- Removing a person signs them out everywhere and deletes their passkeys and push subscriptions.
